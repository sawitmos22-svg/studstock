# StudBolt Stock Management System — Starter Website

เว็บแอป PHP + MySQL สำหรับคลังสินค้า Stud Bolt รองรับผู้จัดการ/พนักงาน, สต๊อกหลาย SKU, รับเข้า/เบิกออก, ประวัติรายการ, Export CSV ที่เปิดด้วย Excel ได้ และสแกน QR Code ผ่านกล้องเบราว์เซอร์ที่รองรับ

## สิ่งที่มีในชุดนี้
- `public/` — จุดเข้าเว็บ/API และไฟล์ที่ browser เรียกใช้
  - `index.php`, `api.php` — จุดเข้าเว็บและ API (ส่งต่อไปยัง controller)
  - `assets/style.css` — CSS ของระบบ
- `app/` — โค้ด PHP ภายใน แบ่งตามหน้าที่
  - `controllers/web.php` — ล็อกอิน, export และข้อมูลหน้าเว็บ
  - `controllers/api.php` — API สำหรับนำเข้าและจัดการข้อมูล
  - `app.php` — ไฟล์ส่งต่อเดิมเพื่อคง URL และการติดตั้งแบบเก่า
  - `config.php` — การเชื่อมต่อ MySQL และ session
  - `views/` — แม่แบบหน้าเว็บแยกตามหัวข้อ
    - `views/login.php` — หน้าเข้าสู่ระบบ
    - `views/layout.php` — ส่วนหัว เมนู และโครงหน้า
    - `views/dashboard/` — ภาพรวม, ทำรายการ, สต๊อก, ประวัติ และหน้าจัดการบัญชี
    - `views/accounts_page.php` — หน้าจัดการบัญชีผู้ใช้และประวัติการเข้าใช้งาน
    - `views/accounts_scripts.php`, `views/log_scripts.php`, `views/scripts.php` — JavaScript ของหน้าเว็บ
    - `views/dialogs.php` — หน้าต่างเพิ่มสินค้าและนำเข้าไฟล์
- `database/` — สคีมาและสคริปต์อัปเกรดฐานข้อมูล
  - `schema.sql` — สร้างฐานข้อมูลและตารางสำหรับติดตั้งใหม่
  - `schema.infinityfree.sql` — สร้างตารางในฐานข้อมูลที่มีอยู่แล้ว
  - `upgrade_*.sql` — สคริปต์อัปเกรดสำหรับฐานข้อมูลเดิม
  - `backups/` — สำรองฐานข้อมูลเดิมสำหรับเก็บไว้ในเครื่อง ไม่ใช้แทน schema สำหรับติดตั้งใหม่
- `index.php`, `api.php`, `app.php`, `config.php`, `style.css` ที่ราก — ไฟล์ทางเข้าเดิมเพื่อให้ URL และการติดตั้งแบบเดิมยังใช้งานได้

## เลือกวิธีวางไฟล์บนโฮสต์

โค้ดชุดเดียวรองรับทั้งสองแบบ:
- **แยก webroot (แนะนำ):** ตั้ง DocumentRoot / Web Root ของโดเมนเป็นโฟลเดอร์ `public/` ส่วน `app/` และ `database/` ให้อยู่เหนือ webroot
- **โฮสต์ที่ตั้ง webroot ไม่ได้ (เช่น shared hosting):** อัปโหลดไฟล์ทางเข้าที่รากพร้อมโฟลเดอร์ `public/`, `app/` และ `database/` ไว้ใน `public_html` หรือ webroot ของโฮสต์ แล้วเข้าเว็บผ่านโดเมนตามปกติ ไฟล์ทางเข้าที่รากจะส่งต่อไปยังโค้ดใน `public/` และไฟล์ `.htaccess` ใน `app/` กับ `database/` ป้องกันการเปิดโฟลเดอร์ภายในโดยตรงบน Apache

ก่อนอัปโหลด ให้ตั้งค่าฐานข้อมูลใน `app/config.php` และไม่ต้องอัปโหลดไฟล์สำรองใน `database/backups/` ขึ้นโฮสต์ ใช้ไฟล์ `database/schema.infinityfree.sql` (หรือ `database/schema.sql` สำหรับฐานข้อมูลที่สร้างเอง) เพื่อติดตั้งตารางแทน

แยกสำเนาโปรเจ็กต์ต่อโฮสต์ได้โดยไม่ต้องคัดลอกโค้ดบางส่วน ให้ตั้งค่าฐานข้อมูลของแต่ละสำเนาใน `app/config.php` และนำเข้า SQL ที่เหมาะกับโฮสต์นั้น

## ติดตั้งในเครื่องด้วย MAMP / XAMPP
1. ต้องมี PHP 8.1+ และ MySQL/MariaDB
2. วางโฟลเดอร์ `studbolt-stock` ใน `htdocs` (XAMPP) หรือโฟลเดอร์เว็บของ MAMP
3. ตั้งค่าฐานข้อมูลใน `app/config.php`
4. สร้างฐานข้อมูลและตารางโดยนำเข้า `database/schema.sql` ผ่าน phpMyAdmin หรือ MySQL CLI
5. เพิ่มบัญชีผู้จัดการในตาราง `users` โดยใช้ hash ที่สร้างจาก `password_hash()` ของ PHP
6. เปิด `http://localhost/studbolt-stock/` แล้วล็อกอิน

หน้าเว็บใช้ DaisyUI 5, Tailwind CSS และตัวอ่าน QR ผ่าน CDN จึงต้องเชื่อมต่ออินเทอร์เน็ตเพื่อโหลดไฟล์ที่เกี่ยวข้อง

## ใช้งานฐานข้อมูลบน InfinityFree
1. สร้าง MySQL Database ใน Control Panel ของ InfinityFree แล้วจดชื่อฐานข้อมูล ชื่อผู้ใช้ และ MySQL Hostname ที่ระบบแสดง
2. เปิด phpMyAdmin จาก Control Panel เลือกฐานข้อมูลที่สร้างไว้ แล้ว Import ไฟล์ `database/schema.infinityfree.sql` (ไฟล์นี้สร้างเฉพาะตารางที่ยังไม่มี ไม่สั่ง `CREATE DATABASE` หรือ `USE` เพราะชื่อฐานข้อมูลบน InfinityFree กำหนดตามบัญชี; นำเข้าซ้ำได้โดยไม่ลบข้อมูลในตารางเดิม)
3. ตั้งค่า `DB_HOST`, `DB_NAME`, `DB_USER` และ `DB_PASS` ใน `app/config.php` ให้ตรงกับข้อมูลจาก Control Panel
4. ตารางที่ได้ยังไม่มีบัญชีผู้ใช้ ต้องสร้างบัญชีผู้จัดการก่อนเข้าสู่ระบบ

สร้าง hash รหัสผ่านด้วย PHP เช่น `php -r "echo password_hash('ใส่รหัสผ่านใหม่', PASSWORD_DEFAULT), PHP_EOL;"` แล้วใช้ hash ที่ได้เพิ่มบัญชีผู้จัดการในตาราง `users` อย่าบันทึกรหัสผ่านแบบข้อความธรรมดาลงฐานข้อมูล

ผู้จัดการตั้งรหัสผ่านใหม่และจัดการบัญชีผู้ใช้เพิ่มเติมได้จากหน้าจัดการผู้ใช้

ผู้จัดการสร้างและลบบัญชีผู้ใช้อื่นได้ที่หน้า “บัญชีผู้ใช้และประวัติ” (`index.php?page=accounts`) โดยไม่สามารถลบบัญชีตัวเองหรือผู้จัดการคนสุดท้ายที่ยังใช้งานได้ ผู้จัดการตั้งรหัสผ่านใหม่ให้บัญชีได้ และกดแสดง/ซ่อนรหัสผ่านใหม่ที่กำลังกรอกได้ แต่ไม่สามารถดูรหัสผ่านเดิมได้เพราะระบบจัดเก็บเป็น hash ทางเดียว การเปลี่ยนรหัสผ่านจะบันทึกในประวัติกิจกรรม ประวัติรับเข้า/เบิกออกและประวัติการลบจะถูกเก็บไว้แม้ลบบัญชีผู้ใช้แล้ว เลือกส่งออกสินค้า บัญชี ประวัติการเข้าใช้งาน และประวัติรับเข้า/เบิกออกเป็นไฟล์ CSV แยกใน ZIP ได้ เลือกลบ log เป็นรายแถวจากตาราง โดยการเลือกครอบคลุมเฉพาะหน้าปัจจุบันและต้องยืนยันก่อนลบ การลบประวัติรับเข้า/เบิกออกไม่เปลี่ยนยอดคงเหลือ และระบบเก็บประวัติการลบไว้ เลือกสิทธิ์บัญชีได้ 3 ระดับ: ผู้จัดการ (สิทธิ์สูงสุด), พนักงานคลัง (รับเข้า/เบิกออก/ปรับยอดสินค้าเดิมเท่านั้น) และพนักงานเบิกสินค้า (เบิกออกเท่านั้น) พนักงานคลังไม่สามารถเพิ่ม SKU นำเข้าสินค้า หรือจัดการบัญชีได้ ไม่มีสิทธิ์ลบสินค้าในทุกบทบาท การรับเข้า เบิกออก และปรับยอดที่พนักงานส่งมาจะเป็นคำขอรอผู้จัดการอนุมัติ โดยระบบยังไม่เปลี่ยนยอดคงเหลือจนกว่าจะได้รับอนุมัติ ผู้จัดการตรวจสอบชื่อผู้ขอ ประเภท จำนวน และรายละเอียดสินค้าได้ที่ `index.php?page=accounts#stock-requests` และอนุมัติหรือปฏิเสธคำขอ รายการที่อนุมัติจะบันทึกประวัติในชื่อผู้ร้องขอพร้อมบันทึกผู้อนุมัติในประวัติกิจกรรม หากยอดสต๊อกเปลี่ยนจนไม่พอ ระบบจะไม่ให้อนุมัติการเบิก รายการรับเข้า/เบิกออกและปรับยอดบันทึกชื่อและชื่อผู้ใช้ ส่วนหน้าเดียวกันแสดงประวัติการเข้าใช้งานและคำขอ/ผลการพิจารณา แบ่งหน้าละ 10 รายการ และหน้าประวัติรับเข้า/เบิกออกก็แบ่งหน้าละ 10 รายการเช่นกัน การอัปเดตฐานข้อมูลเดิมให้รัน `upgrade_activity_logs.sql`, `upgrade_stock_staff_role.sql`, `upgrade_user_deletion.sql` และ `upgrade_stock_approvals.sql` หนึ่งครั้งในฐานข้อมูล `studbolt_stock`; การติดตั้งใหม่จะสร้างตารางและสิทธิ์บทบาทให้อัตโนมัติ

## จัดการสต๊อกสินค้า
ผู้จัดการสามารถเลือก “เคลียร์สต๊อกทั้งหมด” เพื่อปรับยอดคงเหลือทุก SKU เป็น 0 ได้ ระบบเก็บสินค้าและประวัติเดิมไว้ พร้อมบันทึกประวัติการปรับยอดของสินค้าแต่ละรายการที่มียอดคงเหลือ และบันทึกกิจกรรมของผู้ดำเนินการ

## นำเข้าสินค้าจาก Excel / CSV
ตารางรายการสินค้าแสดงหน้าละ 10 รายการ และค้นหาได้จาก SKU, ขนาด, เกรด หรือมาตรฐาน

ผู้จัดการเลือก “นำเข้า CSV / Excel” ในส่วนรายการสินค้าได้ รองรับไฟล์ `.csv` และ `.xlsx` (อ่าน worksheet แรก) ขนาดไม่เกิน 5 MB และไม่เกิน 10,000 รายการ ระบบตรวจสอบข้อมูลก่อนบันทึก หากมีแถวผิดหรือ SKU ซ้ำ จะยกเลิกทั้งไฟล์ และไม่เพิ่มข้อมูลบางส่วน

ดาวน์โหลดเทมเพลตจากปุ่ม “ดาวน์โหลดเทมเพลต” แล้วกรอกข้อมูล โดยใช้หัวคอลัมน์:
- จำเป็น: `sku`, `size_mm`, `length_mm`, `grade`
- ไม่จำเป็น: `diameter_mm`, `standard_name`, `description`, `qty`, `min_qty`, `location_code`

จำนวนตั้งต้น `qty` ที่มากกว่า 0 จะถูกบันทึกเป็นรายการรับเข้าในประวัติด้วย การอ่าน `.xlsx` ต้องเปิด PHP extensions `ZipArchive` และ `SimpleXML` (มีในชุด PHP MAMP ที่ใช้พัฒนาโปรเจ็กต์นี้)

## QR Code
พิมพ์ SKU ของสินค้าไว้ใน QR Code เช่น `SB-M12x80-A4` และพิมพ์รหัสเดียวกันบนฉลากสินค้า เมื่อสแกน ระบบจะค้น SKU ที่ตรงกัน การสแกนใช้กล้องผ่าน `getUserMedia` และตัวอ่าน QR ซึ่งรองรับอุปกรณ์ที่ไม่มี `BarcodeDetector` ด้วย เว็บต้องใช้ HTTPS หรือเปิดผ่าน `localhost` บนเครื่องที่รันเว็บเท่านั้น (localhost บนมือถือหมายถึงตัวมือถือเอง) และต้องอนุญาตสิทธิ์กล้องให้เว็บไซต์
ผู้จัดการสร้างและพิมพ์ฉลาก QR ขนาด 80 × 50 มม. ได้จากปุ่ม “สร้าง QR” ในแถวสินค้า โดย QR จะ encode เฉพาะ SKU เพื่อให้ตรงกับระบบสแกน และไม่ควรใส่รหัสผ่านหรือข้อมูลลับลงใน QR การสร้าง QR ใช้ไลบรารีผ่าน CDN จึงต้องเชื่อมต่ออินเทอร์เน็ต

## วิธีทำงาน
### ผู้จัดการ
1. ล็อกอินด้วยบัญชี manager
2. ตรวจดูภาพรวมและรายการใกล้หมด
3. เพิ่มสินค้าโดยกำหนด SKU ไม่ซ้ำ, ขนาด, ความยาว, เกรด, มาตรฐาน, จำนวนขั้นต่ำ และตำแหน่ง
4. ใช้ประเภท “รับเข้า” เพื่อรับสินค้า; “ปรับยอดคงเหลือ” จะตั้งยอดคงเหลือใหม่ตามจำนวนที่กรอก
5. ส่งออกสินค้าทั้งหมดเป็น CSV จากส่วนรายการสินค้า หรือส่งออกประวัติรับเข้า–เบิกออกเป็น CSV จากส่วนประวัติ (เปิดใน Excel ได้)
6. เปิด “บัญชีผู้ใช้และประวัติ” เพื่อจัดการบัญชี ส่งออกบัญชี และส่งออกประวัติการเข้าใช้งาน
### พนักงาน
1. ล็อกอินด้วยบัญชี staff
2. สแกน QR หรือค้น SKU
3. ตรวจสอบขนาด/ความยาว/เกรด/จำนวนคงเหลือ
4. ใส่จำนวน, เลขที่ใบงาน/โครงการ และหมายเหตุ
5. กด “ยืนยันการเบิกสินค้า”; ระบบป้องกันการเบิกเกินยอดและบันทึกผู้ทำรายการ

## ก่อนใช้งานจริง
นี่คือ starter ที่ใช้งานทดสอบได้ ไม่ใช่ระบบ production ที่ผ่านการตรวจความปลอดภัยแล้ว:
- ติดตั้งหลัง HTTPS และจำกัดสิทธิ์เข้าถึงตามเครือข่ายองค์กร
- เปลี่ยนรหัสผ่านตัวอย่าง และจำกัดหน้าจัดการผู้ใช้ไว้สำหรับผู้จัดการ
- เพิ่ม CSRF protection, rate limiting และนโยบาย backup/restore
- ทดสอบการกู้คืนฐานข้อมูลและการเบิกพร้อมกันหลายคน
- ทดสอบเครื่องสแกนและรูปแบบฉลาก QR จริง
- พิจารณาให้ผู้ดูแลระบบตรวจโค้ดก่อนใช้กับสต๊อกจริง
- บัญชีพนักงานในรุ่นนี้ยังสร้างผ่านฐานข้อมูลโดยผู้ดูแลเท่านั้น
